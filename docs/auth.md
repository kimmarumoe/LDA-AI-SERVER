# 테스트용 회원 인증

## 실행
- 가상 환경에서 `python -m pip install -r requirements.txt`로 의존성을 설치한다.
- `python -m uvicorn app.main:app --host 127.0.0.1 --port 9000`으로 실행한다.
- 프론트엔드를 `http://127.0.0.1:5173` 또는 `http://localhost:5173`에서 연다.
- 아이디는 영문·숫자·밑줄 3~24자이며 대소문자를 구분하지 않는다.
- 닉네임은 공백을 제외한 내용이 있어야 하며 최대 30자다.
- 신규 회원가입 비밀번호는 8~20자이며 회원가입 완료 후 로그인한다.
- 기존 계정 보호를 위해 로그인은 이전 정책인 최대 128자를 허용한다.
- 로그인 실패 시 입력란과 오류 안내를 강조하며, 눈 아이콘으로 비밀번호 표시를 전환한다.

## 작동 흐름과 선택 이유
1. 회원가입 화면이 입력값을 확인하고 `/api/auth/register`로 보낸다.
2. 서버가 다시 검증한 뒤 Argon2 해시로 비밀번호를 변환하고 SQLite에 저장한다.
3. 로그인은 `/api/auth/login`에서 해시와 입력 비밀번호를 비교한다.
4. 서버가 임의의 세션 값을 발급하고 DB에는 그 값의 SHA-256 해시와 만료 시각을 저장한다.
5. 세션 원문은 HttpOnly 쿠키로 전달한다. 프론트엔드의 localStorage에는 저장하지 않는다.
6. `/api/auth/me`가 현재 세션을 검사해 공개 회원 정보만 반환한다.
7. 로그아웃은 `/api/auth/logout`에서 세션과 쿠키를 폐기한다.
8. 닉네임 수정은 `/api/auth/nickname`으로 닉네임만 전송한다. 서버가 로그인 세션으로 회원을 결정한다.
9. 비밀번호 변경은 `/api/auth/password`에서 현재 비밀번호를 검증한 뒤 새 해시를 저장한다.
   해당 회원의 모든 세션을 같은 트랜잭션으로 폐기하고 다시 로그인하도록 한다.

## 프로필 수정과 내비게이션
- 아이디는 수정할 수 없다. 서버 입력 규칙도 닉네임 외의 임의 항목을 거부한다.
- 닉네임은 공백을 제거하여 저장하고 마이페이지와 상단 프로필 이름을 함께 갱신한다.
- 비밀번호는 현재 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력한다.
  새 비밀번호는 현재 비밀번호와 달라야 하며 8~20자다.
- 비밀번호 검증이 실패하면 기존 비밀번호와 로그인 세션은 유지된다.
- 트랜잭션은 여러 DB 변경을 함께 성공하거나 함께 취소하는 처리다.
  비밀번호만 바뀌고 이전 세션이 남는 상태를 피하기 위해 사용했다.
- 화면 입력 검증은 빠른 안내를 위한 것이며, 서버에서도 동일한 규칙을 검사한다.
- LDA 로고는 홈으로 이동한다. 주요 메뉴는 왼쪽, 테마와 계정 메뉴는 오른쪽에 배치한다.
- 계정 메뉴는 기존 Base UI 메뉴를 활용하여 키보드와 Escape 처리를 제공한다.
- 모바일에서는 메뉴 버튼으로 주요 메뉴를 펼치고, 이동하거나 Escape를 누르면 닫는다.

회원 저장은 `auth_store.py`, 요청 처리는 `routers/auth.py`, 입력 규칙은 `schemas/auth.py`로 나눈다.
각 파일에 한 가지 역할을 맡기는 단일 책임 원칙을 적용한다.
SQLite는 별도 DB 서버 없이 로컬에서 실행하기 쉽기 때문에 선택했다.
JWT 대신 서버에 세션을 저장하면 로그아웃할 때 즉시 세션을 폐기하기 쉽다.

## 설정과 데이터
- 기본 회원 DB: `ai-server/data/auth.sqlite3`. `/data/`는 Git에서 제외한다.
- `AUTH_DB_PATH`: DB 경로를 바꿀 때 사용한다.
- `AUTH_ALLOWED_ORIGINS`: 인증 요청을 허용할 프론트엔드 주소를 쉼표로 나열한다.
  미설정 시 `CORS_ALLOW_ORIGINS`를 사용하며 로컬에서는 기본 5173 주소 2개를 허용한다.
- 로컬 환경은 `ENV=local`이다. 그 외 환경에서는 쿠키에 Secure를 적용한다.
- 쿠키는 HttpOnly, SameSite=Lax, 경로 `/api/auth`, 수명 8시간이다.
- 인증 POST는 허용된 Origin과 `X-LDA-Request: auth` 헤더가 필요하다.
- 로컬 프론트엔드는 API의 localhost/127.0.0.1 주소를 현재 화면 호스트와 맞춘다.
  이를 통해 같은 브라우저 사이트로 쿠키가 전달되도록 한다.

## 테스트
`python -m pip install -r requirements-dev.txt` 후
`python -m unittest discover -s tests -v`를 실행한다.
테스트는 임시 DB를 사용하므로 실제 회원 데이터에 영향을 주지 않는다.

## 현재 범위와 배포 전 개발 예정
- 구현: 회원가입, 아이디 로그인, 로그인 상태 복원, 마이페이지 프로필, 닉네임 수정, 비밀번호 변경, 로그아웃.
- 미구현: 작품·분석 기록 저장, 계정 삭제, 비밀번호 복구.
- 예정: 카카오·Google 로그인, 소셜 계정 연결 정책, 요청 횟수 제한과 보안 점검.
- 배포 시 HTTPS, 영구 DB와 백업, 같은 사이트에서 API를 제공하는 프록시 구성을 검토한다.
  현재 SameSite=Lax 쿠키는 서로 다른 사이트에 배포된 프론트엔드와 API 간 인증을 지원하지 않는다.
- 기존 Vercel 프론트엔드와 API가 서로 다른 사이트라면 배포 구조 조정이 먼저 필요하다.

## 공부할 개념
- 해시: 입력을 복원하기 어려운 값으로 바꾸는 방법. 비밀번호 해시와 단순 해시는 목적이 다르다.
- 세션: 서버가 로그인한 사용자를 기억하는 정보.
- 쿠키: 브라우저가 서버에 요청할 때 조건에 맞으면 함께 보내는 작은 값.
- 인증: 누구인지 확인하는 과정. 권한 확인은 무엇을 할 수 있는지 확인하는 별도 과정.
- CSRF: 다른 사이트가 사용자의 로그인 상태를 이용해 요청하도록 유도하는 공격.
- React Context: 여러 화면이 공통 상태를 공유하는 방법.
