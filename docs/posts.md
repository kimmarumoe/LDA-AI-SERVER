# 작품 공유 게시판

## 사용 흐름

로그인 후 완성한 작품을 계정에 저장하고, 작품 상세의 ‘이 작품 공유하기’ 또는 게시판의 ‘작품 공유하기’를 선택합니다. 제목(공백 제거 후 1~100자), 설명(1~5000자), 본인 작품을 입력해 게시합니다. 글 내용은 서식 없는 텍스트이며 HTML로 실행하지 않습니다.

비로그인 사용자도 목록, 작품과 조립 가이드를 볼 수 있습니다. 작성자만 제목·설명을 수정하거나 글을 삭제할 수 있습니다. 댓글과 좋아요도 함께 제공하며, 작품 자체의 교체·대댓글·댓글 좋아요·신고는 포함하지 않습니다. 사용자의 로그인 아이디와 비밀번호는 공개 응답에 포함하지 않습니다. 작성자 닉네임은 현재 회원 정보를 사용합니다.

## API

기존 세션 쿠키의 `/api/auth` 경로를 유지하기 위해 공개 읽기와 인증 쓰기를 `/api/auth/posts` 아래에 둡니다. GET에는 로그인이 필요하지 않습니다.

- `GET /api/auth/posts?offset=0&limit=12`: 최신순 `{ items, hasMore }`. limit은 1~24. 목록에는 설명 앞 160자와 최대 24×24칸의 색상 썸네일을 포함하고 전체 가이드는 제외합니다.
- `GET /api/auth/posts/{id}`: 작품 복사본과 조립 단계, `canEdit`, `likedByMe`, 댓글·좋아요 개수를 반환. 쿠키에 따라 수정 가능 여부가 달라지므로 모든 응답은 `Cache-Control: no-store`입니다.
- `POST /api/auth/posts`: `{ workId, title, description }`로 게시(201). 서버가 본인 작품인지 검사하고 저장된 데이터에서 복사합니다.
- `PATCH /api/auth/posts/{id}`: `{ title, description }`로 수정(200).
- `DELETE /api/auth/posts/{id}`: 본인 글 삭제(204).

쓰기는 로그인 쿠키와 허용된 Origin, `X-LDA-Request: auth` 헤더가 필요합니다. 미로그인은 401, 없는 글과 타인 글 수정·삭제는 404, 잘못된 입력은 422입니다.

## 데이터 유지

기존 회원 DB에 `posts` 테이블과 정렬 인덱스를 추가 생성합니다. 원본 작품에 대한 외래 키를 만들지 않고 분석 결과와 조립 단계를 JSON 복사본으로 보관합니다. 따라서 개인 작품 수정·삭제는 이미 게시한 내용에 영향을 주지 않습니다. 게시글 삭제도 개인 작품에 영향을 주지 않습니다. DB 파일을 유지하면 서버 재시작 후에도 글이 유지됩니다.

공개 게시판의 초기 버전으로, 운영 배포용 신고·관리자 처리, 요청 빈도·저장량 제한은 별도 작업입니다.

## 검증

`.venv/bin/python -m unittest discover -s tests`로 기존 인증·작품 테스트와 게시판 테스트를 실행합니다. 게시판 테스트는 임시 DB에서 공개 조회, 개인정보 필드 제외, 소유권, 요청 출처, 입력 검증, 원본과의 독립성, 페이지 분리, 저장 후 재연결을 확인합니다.


## 댓글·좋아요

목록과 상세에는 `commentCount`, `likeCount`를 표시합니다. 상세의 `likedByMe`와 댓글의 `canEdit`는 현재 로그인 세션에 따라 달라집니다. 로그인 아이디·회원 번호·비밀번호는 공개 응답에 포함하지 않습니다.

- `GET /api/auth/posts/{id}/comments?offset=0&limit=20`: 공개 조회. 최신 작성 순으로 `{ items, hasMore, total }` 반환. limit은 1~20입니다.
- `POST /api/auth/posts/{id}/comments`: `{ content }`로 댓글 작성(201). 공백 제거 후 1~1000자입니다. `{ comment, commentCount }`를 반환합니다.
- `PATCH /api/auth/posts/{id}/comments/{comment_id}`: 본인 댓글만 수정(200). 작성 시각은 유지하고 수정 시각·표시를 갱신합니다.
- `DELETE /api/auth/posts/{id}/comments/{comment_id}`: 본인 댓글만 삭제하고 `{ commentCount }` 반환(200).
- `PUT /api/auth/posts/{id}/like`: 좋아요 등록. 반복 호출해도 1건만 유지합니다.
- `DELETE /api/auth/posts/{id}/like`: 본인 좋아요 취소. 반복 호출해도 다른 회원의 좋아요는 삭제하지 않습니다.
- 좋아요 응답은 `{ likedByMe, likeCount }`(200)이며, 서버의 결과를 받은 후 화면을 갱신합니다.

모든 쓰기는 세션과 기존 요청 출처 검증이 필요합니다. 게시글 작성자라도 다른 사람의 댓글을 수정·삭제할 수 없습니다. 다른 게시글 주소로 댓글 번호를 옮겨 요청해도 관리할 수 없습니다.

새 `post_comments`, `post_likes` 테이블을 기존 DB에 추가합니다. 회원·작품·게시글 테이블과 기존 데이터는 유지합니다. 좋아요의 `(post_id, member_id)` 기본 키가 동시·반복 등록을 막습니다. 게시글을 삭제하면 외래 키의 `ON DELETE CASCADE`로 그 글의 댓글·좋아요만 함께 삭제됩니다. 개인 작품과 다른 게시글의 반응은 유지됩니다.

화면에서는 댓글 삭제 전 확인하고, 실패하면 작성·수정 입력과 삭제 확인창을 유지합니다. 새 댓글 작성 시 첫 페이지로 돌아가며, 마지막 페이지의 마지막 댓글을 지우면 이전 페이지로 이동합니다. 세션 만료 시 안내와 재로그인 버튼을 제공합니다. 다른 사용자의 변경은 새로 조회할 때 반영하며 실시간 알림은 포함하지 않습니다.

`tests/test_post_social.py`에서 댓글 권한·게시글 경계·입력·페이지 분리·개수·기존 게시글 유지·연쇄 삭제·좋아요 반복/동시 요청을 검증합니다.
