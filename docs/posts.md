# 작품 공유 게시판

## 사용 흐름

로그인 후 완성한 작품을 계정에 저장하고, 작품 상세의 ‘이 작품 공유하기’ 또는 게시판의 ‘작품 공유하기’를 선택합니다. 제목(공백 제거 후 1~100자), 설명(1~5000자), 본인 작품을 입력해 게시합니다. 글 내용은 서식 없는 텍스트이며 HTML로 실행하지 않습니다.

비로그인 사용자도 목록, 작품과 조립 가이드를 볼 수 있습니다. 작성자만 제목·설명을 수정하거나 글을 삭제할 수 있습니다. 작품 자체의 교체, 댓글·좋아요·신고는 포함하지 않습니다. 사용자의 로그인 아이디와 비밀번호는 공개 응답에 포함하지 않습니다. 작성자 닉네임은 현재 회원 정보를 사용합니다.

## API

기존 세션 쿠키의 `/api/auth` 경로를 유지하기 위해 공개 읽기와 인증 쓰기를 `/api/auth/posts` 아래에 둡니다. GET에는 로그인이 필요하지 않습니다.

- `GET /api/auth/posts?offset=0&limit=12`: 최신순 `{ items, hasMore }`. limit은 1~24. 목록에는 설명 앞 160자와 최대 24×24칸의 색상 썸네일을 포함하고 전체 가이드는 제외합니다.
- `GET /api/auth/posts/{id}`: 작품 복사본과 조립 단계, `canEdit` 반환. 쿠키에 따라 수정 가능 여부가 달라지므로 모든 응답은 `Cache-Control: no-store`입니다.
- `POST /api/auth/posts`: `{ workId, title, description }`로 게시(201). 서버가 본인 작품인지 검사하고 저장된 데이터에서 복사합니다.
- `PATCH /api/auth/posts/{id}`: `{ title, description }`로 수정(200).
- `DELETE /api/auth/posts/{id}`: 본인 글 삭제(204).

쓰기는 로그인 쿠키와 허용된 Origin, `X-LDA-Request: auth` 헤더가 필요합니다. 미로그인은 401, 없는 글과 타인 글 수정·삭제는 404, 잘못된 입력은 422입니다.

## 데이터 유지

기존 회원 DB에 `posts` 테이블과 정렬 인덱스를 추가 생성합니다. 원본 작품에 대한 외래 키를 만들지 않고 분석 결과와 조립 단계를 JSON 복사본으로 보관합니다. 따라서 개인 작품 수정·삭제는 이미 게시한 내용에 영향을 주지 않습니다. 게시글 삭제도 개인 작품에 영향을 주지 않습니다. DB 파일을 유지하면 서버 재시작 후에도 글이 유지됩니다.

공개 게시판의 초기 버전으로, 운영 배포용 신고·관리자 처리, 요청 빈도·저장량 제한은 별도 작업입니다.

## 검증

`.venv/bin/python -m unittest discover -s tests`로 기존 인증·작품 테스트와 게시판 테스트를 실행합니다. 게시판 테스트는 임시 DB에서 공개 조회, 개인정보 필드 제외, 소유권, 요청 출처, 입력 검증, 원본과의 독립성, 페이지 분리, 저장 후 재연결을 확인합니다.
