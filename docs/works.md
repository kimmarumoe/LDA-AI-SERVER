# 내 작품 저장·불러오기

로그인한 회원이 분석과 조립 가이드 생성까지 완료한 결과를 저장합니다. 샘플도 저장할 수 있으며 원본 업로드 이미지는 보관하지 않습니다.

## API와 권한

- `POST /api/auth/works`: `{ title, analysis, steps, options }`를 받아 `{ id, title, createdAt }` 반환(201).
- `GET /api/auth/works`: 본인 작품의 요약 목록을 최신 저장 순으로 반환(200).
- `GET /api/auth/works/{work_id}`: 요약과 `analysis`, `steps`, `options` 반환(200).
- `PATCH /api/auth/works/{work_id}`: `{ title }`로 본인 작품 이름 변경, 작품 요약 반환(200). 이름 외 필드는 허용하지 않습니다.
- `DELETE /api/auth/works/{work_id}`: 본인 작품 삭제(204). 없는 작품·타인 작품은 404입니다.
- 미로그인은 401, 없는 작품과 다른 사람의 작품은 모두 404입니다.
- 저장·이름 변경·삭제는 허용된 `Origin`과 `X-LDA-Request: auth` 헤더가 필요합니다.
- 이름은 공백 제거 후 1~80자이며, 분석 브릭·메타와 비어 있지 않은 조립 단계가 필요합니다.
- 검증된 JSON은 UTF-8 기준 12MiB까지입니다. 요청 수신 전 본문 제한은 아닙니다.

## 저장 방식과 선택 이유

기존 회원 DB(`AUTH_DB_PATH`, 기본 `data/auth.sqlite3`)에 작품 테이블과 소유자·시각 인덱스를 최초 작품 요청 시 생성합니다. 회원 데이터는 유지합니다.

소유자 ID는 서버가 로그인 세션에서 확인합니다. 조회 SQL도 작품 ID와 소유자 ID를 함께 검사합니다. 목록에는 큰 분석 결과를 제외해 목록 조회 부담을 줄입니다.

만료되는 임시 분석 번호 대신 결과 전체를 JSON 스냅샷으로 저장합니다. 저장한 분석 번호는 제거하며, 별도 옵션도 함께 보관합니다. DB 파일을 유지하면 서버 재시작 후에도 작품을 열 수 있습니다. 배포 시에는 DB 저장 공간 유지와 백업이 필요합니다.

프론트엔드는 `/mypage/works/:workId`에서 조회하므로 직접 접속·새로고침도 지원합니다. 화면 표시, API 통신, DB 저장은 각 파일로 분리합니다.

## 검증

`.venv/bin/python -m unittest discover -s tests -v`로 임시 DB 기반 테스트를 실행합니다. 소유권·로그아웃·요청 출처·입력·정렬·재연결·실제 분석 저장을 검증합니다.

작품 상세에서 이름 수정 버튼을 눌렀을 때만 입력란을 표시합니다. 취소하면 저장하지 않으며, 실패하면 입력을 유지해 재시도할 수 있습니다. 이름 변경은 분석 결과·조립 단계·저장 시각을 바꾸지 않습니다. 삭제 전에는 복구할 수 없음을 확인하고, 성공 후 마이페이지로 이동합니다. 공개 게시글은 별도 복사본이므로 개인 작품 이름 변경·삭제 후에도 유지됩니다.

기존 작품 테이블 구조를 그대로 사용하므로 DB 마이그레이션은 필요하지 않습니다. 테스트는 소유권·요청 출처·이름 길이·재조회·삭제 범위와 공개 게시글 유지를 함께 확인합니다.

원본 이미지 보관, 모든 분석 시도의 자동 기록, 운영 배포 검증은 이번 범위에 포함하지 않습니다.
